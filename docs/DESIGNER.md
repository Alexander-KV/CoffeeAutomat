# Перестановка модулей в Visual Studio

Откройте CoffeeAutomat.sln в Visual Studio 2022 (17.8 или новее) с компонентами разработки классических приложений .NET. Сначала выполните «Сборка → Перестроить решение»: дизайнеру нужны собранные пользовательские элементы управления. NuGet восстановит Microsoft.WinForms.Designer.SDK — поддержку вложенных модулей в конструкторе .NET 8.

## Увидеть всё приложение

Откройте `Forms/MainForm.cs` → **Shift+F7**. Это главное окно с шапкой, кнопкой администратора и полноценным автоматом в начальном состоянии покупателя. Предпросмотр использует настоящий `CoffeeMachineControl`, а не картинку или отдельную копию интерфейса. Сохранённые пользовательские JSON в конструкторе не читаются: показано стандартное меню. При запуске программа подключает сохранённые автоматы.

Основная точка редактирования теперь **`Forms/MainForm.cs` → Shift+F7**. На полной форме можно выбирать автомат и вложенные `SelectionModule`, `PaymentModule`, `DispensingModule`. Их открывает для конструктора `CoffeeMachineDesigner`. Если мышью выбирается весь автомат, используйте «Структуру документа» или **F4 → Модули → PaymentModule → Location / Size** (аналогично для остальных блоков).

При запуске используется сам автомат из формы. Дополнительные автоматы получают его размер и расположение трёх модулей. Изменения в `MainForm.Designer.cs` больше не теряются при замене предпросмотра новым элементом.

`Forms/CoffeeMachineControl.cs` можно по-прежнему открывать отдельно, если удобнее редактировать общий шаблон автомата без шапки приложения.

Корпус рисуется базовым классом `CoffeeMachineSurface`: это позволяет дизайнеру корневого элемента отображать ту же отрисовку, которая используется при запуске. Внешний вид не заменён стандартными серыми панелями.

## Переместить целый блок

1. В обозревателе решений откройте `CoffeeMachineApp2/Forms/MainForm.cs`.
2. Нажмите **Shift+F7** или правую кнопку → **Просмотреть конструктор**. Открывайте основной `.cs`, а не вложенный `.Designer.cs`.
3. Выберите вложенный `SelectionModule` (экран выбора), `PaymentModule` (терминал) или `DispensingModule` (приготовление и выдача) у `machinePreview`.
4. Перетащите блок мышью; размер меняйте за маркеры или через **F4 → Location / Size**. Если мешает вложенный элемент, выберите нужный модуль в **Вид → Другие окна → Структура документа**.
5. Сохраните и запустите проект. Раскладка сохранена в `.Designer.cs` и применяется ко всем экземплярам автомата.

## Переместить карту или лоток внутри блока

Откройте через Shift+F7 нужный файл в `Forms/Modules`:

| Файл | Что можно переставлять |
|---|---|
| `PaymentControl.cs` | `_cardSlot` — карта, `_display` — дисплей, кнопки способа оплаты, купюры и оплата |
| `DispensingControl.cs` | `preparationView` — приготовление, `changeTrayView` — сдача, подписи и кнопка получения кофе |
| `CoffeeSelectionControl.cs` | `menuModule` — каталог, `orderModule` — параметры заказа |
| `BeverageMenuControl.cs` | Заголовки, фильтры, сетка карточек, перелистывание |
| `OrderOptionsControl.cs` | Стоимость, сахар, молоко, сироп, переход к оплате |

Например, чтобы опустить карту: откройте `PaymentControl.cs` в конструкторе, выберите `_cardSlot`, увеличьте `Location.Y` и переместите соседние элементы, чтобы они не перекрывались. При необходимости увеличьте высоту терминала. В таблицах положение управляется строками и столбцами, поэтому для перестановки карточек используйте параметры таблицы.

## Изменение размеров

`ScalableControl` хранит исходные координаты дочерних элементов и пропорционально меняет их границы, шрифты, отступы и абсолютные размеры строк таблиц. Вложенный модуль отвечает за своё содержимое; повторное DPI-масштабирование детей отключено. Жёсткие минимальные размеры терминала и меню убраны.

Изменение `machinePreview.Size` на форме масштабирует весь автомат; изменение `PaymentModule.Size` масштабирует только терминал. Для сохранения пропорций меняйте ширину и высоту в одинаковое число раз. Например, 640×1000 → 480×750. Ручное перемещение блока сохраняется при следующем изменении размера.

При запуске автомат дополнительно уменьшается до доступной высоты окна, чтобы выдача оставалась видимой. Несколько автоматов расположены рядом; при нехватке ширины прокручивается площадка целиком. Ручная перестановка остаётся ответственностью разработчика: если положить два блока друг на друга, программа не меняет ваш замысел автоматически.

## Почему это соответствует ООП

Весь автомат — повторно используемый `UserControl`. Он состоит из вложенных `UserControl`, каждый отвечает за свою часть интерфейса. Модули передают намерения событиями; `CoffeeMachineControl` вызывает прежнюю модель покупки и обновляет отображение. `InitializeComponent()` хранит раскладку, а `Bind()` подключает работающую модель, обработчик сохранения и доступ администратора. Конструктор без параметров позволяет дизайнеру создать элемент без открытия JSON или входа администратора.

Картинки для предварительного просмотра встроены в сборку; это те же исходные изображения. Свойства состояния модели скрыты от сериализации дизайнера. Обновление цены, оплаты и выдачи не присваивает модулям новые координаты.

Покупатель и администратор приложения не переставляют блоки: это редактирование исходного интерфейса в Visual Studio. Положение модулей не хранится в пользовательском `machines.json`.

Сборка и проверки модели выполняются также на Linux. Открытие самого конструктора и проверка перетаскивания требуют Visual Studio на Windows.

Отдельная проверка геометрии на Windows:

```powershell
dotnet run --project CoffeeMachineApp.UiTests/CoffeeMachineApp.UiTests.csproj
```

Она проверяет уменьшение/увеличение, возврат к исходным размерам, сохранение переставленных блоков, размеры шрифта после обновления оплаты, отсутствие пересечения модулей и размещение двух автоматов в окне. При успешном прохождении сохраняется `artifacts/ui/main-form.png`. Это проверка WinForms во время выполнения; она не заменяет ручную проверку сохранения формы в дизайнере VS. На Linux этот проект можно собрать, но запустить нельзя.

## Ошибка CreateAppHost: отказано в доступе к CoffeeMachineApp.dll

Это отказ Windows в доступе к промежуточному файлу сборки, а не исключение при покупке кофе. Сам текст ошибки не определяет, какой процесс или правило доступа мешает.

1. Остановите отладку, закройте приложение и Visual Studio.
2. Распакуйте свежий архив целиком в новую обычную папку, например `C:\Projects\CoffeeAutomat`, вне рабочего стола и синхронизируемых папок. Не открывайте решение внутри ZIP.
3. В старой копии можно удалить только сгенерированные папки `bin` и `obj` внутри `CoffeeMachineApp2` и `CoffeeMachineApp.Tests`. Если Windows не разрешает удаление, перезагрузите компьютер, затем повторите. Исходники и данные в `%LOCALAPPDATA%\CoffeeMachineApp` не удаляйте.
4. Откройте решение из новой папки и выполните «Сборка → Перестроить решение».
5. Если отказ остаётся даже в новой папке, проверьте доступ на запись и журнал защиты Windows: там может быть указана блокировка. Не отключайте защиту и не запускайте Visual Studio от администратора ради обхода ошибки.

Изменение `UseAppHost` не устраняет причину недоступности DLL, поэтому создание обычного Windows EXE сохранено.
