# Интерфейс: окна, элементы управления и отрисовка

[Оглавление руководства](DEFENSE.md) · [Короткая шпаргалка](QUICK_DEFENSE.md)

Интерфейс находится в `CoffeeMachineApp2/Forms`. Он создаётся обычным кодом C#: конструкторы создают кнопки, подписи и панели, задают их размеры и подписывают обработчики на события. Отдельных файлов дизайнера `.Designer.cs` у этих окон нет.

`Form` — самостоятельное окно, `UserControl` — составной элемент, который можно поместить в окно, `Control` — базовый элемент интерфейса, `Button` — кнопка. Поэтому `MainForm` и `AdminForm` наследуются от `Form`, один автомат представлен `CoffeeMachineControl : UserControl`, а нарисованные карта и лоток остаются кнопками с обычным событием `Click`.

Основная последовательность работы: пользователь нажимает кнопку → обработчик вызывает метод `CoffeeMachine` → модель проверяет допустимость действия и меняет своё состояние → `RefreshView()` обновляет надписи и доступность кнопок. Цена заказа берётся из модели; рисунок чашки и расположение карточек относятся к интерфейсу.

В таблицах ниже перечислены все явно объявленные конструкторы и методы этих UI-классов, в том числе закрытые методы и переопределения. Свойства и обработчики, записанные прямо в виде лямбд, разобраны отдельно. Окно `AdminLoginForm` описывается в разделе о доступе администратора.

## `MainForm` — главное окно со всеми автоматами

Файл: [MainForm.cs](../CoffeeMachineApp2/Forms/MainForm.cs). Класс `public sealed class MainForm : Form` размещает экземпляры автоматов, загружает их настройки, сохраняет общий список и переключает режим покупателя/администратора. `sealed` запрещает создавать наследников этого класса.

Ключевые поля:

| Поле | Для чего нужно |
|---|---|
| `_store : IMachineStore` | Источник загрузки и сохранения настроек. Окну достаточно методов интерфейса; детали записи JSON находятся в `JsonMachineStore`. |
| `_access : AdminAccess` | Один общий сеанс администратора для всех автоматов. Путь `admin-access.json` строится рядом с `JsonMachineStore.DefaultPath`. |
| `_machines : List<CoffeeMachineControl>` | Все отображаемые автоматы. У каждого элемента своя модель `CoffeeMachine`. |
| `_floor : FlowLayoutPanel` | Размещает автоматы слева направо. Здесь прокрутка разрешена, поскольку несколько корпусов могут не поместиться в окно. |
| `_count`, `_modeHint` | Показывают число автоматов и текущий режим. |
| `_add`, `_adminButton` | Создание автомата и вход/выход администратора. |

| Метод | Что делает |
|---|---|
| `public MainForm(IMachineStore store)` | Сохраняет переданное хранилище, создаёт общий `AdminAccess`, строит заголовок, область автоматов и нижнюю подпись. Загружает настройки через `_store.Load()`, вызывает `Attach()` для каждой конфигурации, затем `RefreshMode()`. Подписывает проверку незавершённых заказов на `FormClosing`. |
| `private void Attach(MachineConfiguration configuration)` | Создаёт новую модель `CoffeeMachine` и соответствующий `CoffeeMachineControl`. Передаёт ему `SaveConfiguration` и общий доступ администратора. Подписывает события копирования и удаления, добавляет элемент в список и на экран. |
| `private void AddMachine(MachineConfiguration source)` | Проверяет права администратора и ограничение в 12 автоматов. Находит свободное имя `Кофейня №N`, вызывает `source.Duplicate(...)`, сначала сохраняет расширенный список, затем добавляет новый автомат на экран и прокручивает общее пространство к нему. Ошибки показываются сообщением. |
| `private void RemoveMachine(CoffeeMachineControl view)` | Проверяет права. Не удаляет последний автомат и автомат с текущим заказом. После подтверждения сначала сохраняет список без удаляемого экземпляра, затем удаляет его из коллекции и панели, вызывает `Dispose()` и обновляет счётчик. |
| `private void SaveConfiguration(MachineConfiguration updated)` | Проверяет права администратора. Строит новый список конфигураций: элемент с совпадающим ID заменяется на `updated`, остальные сохраняются. Передаёт весь список хранилищу. |
| `private void SwitchMode(object sender, EventArgs e)` | Если администратор уже вошёл, выполняет `Logout()`. Для входа сначала проверяет отсутствие заказов у всех автоматов, затем открывает `AdminLoginForm` через `ShowDialog(this)` и обновляет интерфейс. |
| `private void RefreshMode()` | Меняет видимость кнопки нового автомата и подписи режима, текст и выделение кнопки администратора. Вызывает `RefreshAccess()` у всех автоматов, затем обновляет счётчик. |
| `private void UpdateCount()` | Формирует строку с числом автоматов; в режиме администратора дополнительно сообщает, что покупки приостановлены. |

Важные события, назначенные в конструкторе и `Attach()`:

- Кнопка нового автомата вызывает `AddMachine(MachineConfiguration.CreateDefault())`; копирование вызывает тот же метод, но передаёт настройки выбранного автомата.
- `DuplicateRequested` и `RemoveRequested` сообщают главному окну о запросе. Сам отдельный автомат не управляет коллекцией соседей.
- `FormClosing` проверяет `Machine.Order != null`. При незавершённых заказах пользователь подтверждает выход; ответ «Нет» устанавливает `e.Cancel = true`.

Новый сосед получает отдельную модель и отдельное состояние покупки. Копируются настройки, а не текущий заказ, таймер, вставленная карта или сдача. Перед изменением состава автоматов сначала выполняется запись, поэтому обычная ошибка сохранения не удаляет и не добавляет элемент только на экране.

## `CoffeeMachineControl` — один автомат целиком

Файл: [CoffeeMachineControl.cs](../CoffeeMachineApp2/Forms/CoffeeMachineControl.cs). Класс `public sealed class CoffeeMachineControl : UserControl` объединяет корпус, меню, параметры заказа, терминал, чашку и лоток сдачи. Он связывает действия пользователя с моделью `CoffeeMachine`.

Ключевые поля, свойства и события:

| Член | Назначение |
|---|---|
| `Machine { get; }` | Модель именно этого автомата. Свойство позволяет главному окну читать его состояние и конфигурацию. |
| `DuplicateRequested`, `RemoveRequested` | События запроса на копирование и удаление. Подписчик — `MainForm`. |
| `_save : Action<MachineConfiguration>` | Переданная функция сохранения. В данном приложении ведёт к `MainForm.SaveConfiguration()`. |
| `_access` | Общий сеанс администратора, полученный от главного окна. |
| `_menu`, `_cards` | Таблица видимых карточек и соответствие каждой кнопки её напитку. Словарь нужен для обновления выделения и доступности. |
| `MenuColumns = 3`, `MenuRows = 2`, `MenuPageSize = 6` | Размер одной страницы меню. Это количество карточек на странице, а не ограничение всего меню. |
| `_filter`, `_page`, `_pageCount` | Текущая категория, номер страницы с нуля и число страниц. |
| `_previousPage`, `_nextPage`, `_pageLabel`, `_filters` | Перелистывание страниц и фильтры «Всё меню», «Без молока», «С молоком». |
| `_timer` | `System.Windows.Forms.Timer` с интервалом 40 мс. Вызывает `Tick()` для обновления приготовления и пара. |
| `_brewing : Stopwatch` | Измеряет фактически прошедшее время приготовления. Прогресс не вычисляется простым подсчётом вызовов таймера. |
| `_dispenser : PreparationView` | Рисует стакан и приготовление по переданным значениям. |
| `_cardSlot`, `_changeTray` | Визуальные кнопки карты и сдачи со своими анимациями. |
| `_notes` | Кнопки внесения 10, 50, 100 и 500 рублей. |
| `_tips` | Подсказки с названием и описанием напитка. |
| `_error`, `_message` | Признак ошибки и строка обратной связи пользователю. |
| Остальные подписи и кнопки | Заголовок, шаг заказа, цена, сахар, молоко, сироп, переход к оплате, отмена, выдача чашки и действия администратора. Их значения выставляются в `RefreshView()`. |

| Метод | Что делает |
|---|---|
| `public CoffeeMachineControl(CoffeeMachine machine, Action<MachineConfiguration> save, AdminAccess access)` | Принимает модель, функцию сохранения и доступ администратора. Строит все части автомата, настраивает размеры и масштабирование, назначает обработчики кнопкам и таймеру. В конце создаёт меню и применяет текущий режим доступа. |
| `public void RefreshAccess()` | Показывает либо скрывает настройки, копирование и удаление. Выводит сообщение о режиме и вызывает `RefreshView()`. |
| `private static Label TextAt(Control parent, string text, Rectangle bounds, Font font, Color color)` | Создаёт подпись с заданными координатами и оформлением, добавляет её в родительский элемент и возвращает ссылку. Длинный текст отображается с многоточием. |
| `private static RoundedButton Place(Control parent, string text, Rectangle bounds, EventHandler click, bool primary = false)` | Создаёт оформленную кнопку через `UiStyle.Button()`, задаёт положение, помещает в родителя и возвращает её. |
| `protected override void OnPaint(PaintEventArgs e)` | Рисует корпус, рамку экрана, нишу выдачи, декоративные линии и индикатор готовности. Масштабирует базовые координаты 640 × 1000 под фактический размер элемента. |
| `private void PaintTerminal(object sender, PaintEventArgs e)` | Обработчик события `Paint` панели терминала. Рисует декоративную прорезь для наличных, используя базовый размер 152 × 640. |
| `private void BuildMenu()` | Освобождает старые карточки и их изображения, фильтрует меню, вычисляет число страниц, ограничивает текущую страницу допустимым диапазоном. Берёт до шести напитков через `Skip(...).Take(...)` и создаёт кнопки в сетке. Для пустой категории помещает одну подпись на всю сетку. Обновляет счётчик и видимость стрелок. |
| `private void ChangePage(int direction)` | Разрешает перелистывание только покупателю на стадии выбора. Прибавляет `direction` к номеру страницы, ограничивает результат через `Math.Clamp`, затем перестраивает меню и обновляет интерфейс. Заказ не сбрасывает. |
| `private void Configure(int sugarDelta = 0, bool milk = false, bool syrup = false)` | Если заказ выбран, вычисляет новые параметры: сахар в диапазоне 0–4, включение/выключение дополнительного молока, следующий сироп. Через `Act()` передаёт параметры в `Machine.Configure()`. Сироп переключается по кругу: без сиропа → ваниль → карамель → без сиропа. |
| `private void CancelOrBack(object sender, EventArgs e)` | Через `Act()` вызывает `BackToSelection()` при оплате или `Cancel()` при выборе. Показывает сумму возвращённых наличных либо подсказку о возврате к выбору. |
| `private void SwitchPayment(bool card)` | Через `Act()` выбирает способ оплаты в модели. Если модель вернула наличные при переходе на карту, сообщает сумму; иначе подсказывает, как вставить карту или внести деньги. |
| `private void OpenAdmin(object sender, EventArgs e)` | Проверяет режим администратора, открывает `AdminForm` модально. Переданный редактору обработчик сначала вызывает `_save(config)`, а затем `Machine.UpdateConfiguration(config)`. После закрытия обновляет название и меню автомата. |
| `private void Tick(object sender, EventArgs e)` | Во время приготовления вычисляет прогресс как прошедшие секунды / `PrepareSeconds`, обновляет анимацию, описание этапа и оставшееся время. При достижении 100% вызывает `Machine.FinishPreparing()`. Если чашка уже готова и ещё не получена, продолжает движение пара; в остальных ненужных состояниях останавливает таймер. |
| `private void RefreshView()` | Читает режим доступа и состояние модели, затем согласованно обновляет весь интерфейс: доступность и выделение кнопок, цены, параметры заказа, оплату, карту, сдачу, чашку, сообщения и декоративный индикатор. Вызывает `Invalidate()` для новой отрисовки корпуса. |
| `private void Notify(string text)` | Снимает признак ошибки и заменяет текст сообщения пользователю. |
| `private void Act(Action action)` | Общая обёртка действий покупателя. Блокирует их в режиме администратора, выполняет переданное действие, показывает `InvalidOperationException` и `ArgumentException` как сообщение интерфейса, затем вызывает `RefreshView()`. |
| `protected override void Dispose(bool disposing)` | При освобождении управляемых ресурсов освобождает таймер, подсказки и созданные для карточек копии изображений. Затем передаёт освобождение дочерних элементов базовому классу. |

Обработчики коротких действий записаны прямо в конструкторе или `BuildMenu()`, поэтому у них нет отдельных имён методов:

| Событие | Последовательность действий |
|---|---|
| Нажатие категории | Меняет `_filter`, сбрасывает `_page` в 0, вызывает `BuildMenu()` и `RefreshView()`. |
| Нажатие карточки напитка | Внутри `Act()` вызывает `Machine.Select(id)` и выводит описание рецепта. |
| Нажатие перехода к оплате | Вызывает `Machine.BeginPayment()`, затем предлагает выбрать способ оплаты. |
| Нажатие карты | Если карта уже вставлена, вызывает `Machine.EjectCard()`. Иначе выбирает оплату картой, возвращает внесённые наличные при необходимости и вызывает `Machine.InsertCard()`. |
| `CardSlotView.AnimationFinished` | Вызывает `RefreshView()`: после завершения вставления может стать доступна кнопка оплаты. |
| Нажатие номинала наличных | Вызывает `Machine.InsertMoney(amount)`. |
| Нажатие «Оплатить» | Сначала вызывает `Machine.Pay()`. Только при успехе перезапускает `Stopwatch`, запускает таймер приготовления и показывает сообщение. |
| Нажатие «Забрать кофе» | Вызывает `Machine.CollectDrink()`, останавливает таймер пара, напоминает о сдаче или карте, если они ещё не получены. |
| Нажатие лотка сдачи | Вызывает `Machine.CollectChange()` и сообщает реально возвращённую моделью сумму. |
| Копирование / удаление | Порождает `DuplicateRequested` / `RemoveRequested`; состав автоматов меняет главное окно. |
| `_timer.Tick` | Вызывает именованный метод `Tick()`. |

Как устроена пагинация: сначала выбирается категория, затем вычисляется `Math.Max(1, (числоНапитков + 5) / 6)`. Например, для 13 напитков будет три страницы: 6, 6 и 1 карточка. `_page` хранится с нуля, но пользователю показывается `_page + 1`. После удаления напитков номер ограничивается новым числом страниц. Выбранный заказ хранится в `Machine.Order`, поэтому исчезновение его карточки с текущей страницы не теряет выбор. При возвращении на страницу `RefreshView()` выделяет карточку по ID.

Внутри меню нет прокрутки: таблица имеет три процентных столбца, две процентных строки, фиксированное число ячеек и `AutoScroll = false`; кнопки занимают свои ячейки через `Dock = Fill`. Это отличается от общего пространства `MainForm._floor`, где прокрутка между автоматами сохранена.

Покупатель может менять параметры конкретной порции — сахар, дополнительное молоко, сироп. Изменение самого меню, цен и состава автоматов разрешено только в режиме администратора. Пока оплаченный заказ не завершён, модель сохраняет его: отдельно нужно забрать чашку, сдачу и карту. Интерфейс показывает эти оставшиеся действия и не завершает заказ самостоятельно.

## `AdminForm` — редактор настроек одного автомата

Файл: [AdminForm.cs](../CoffeeMachineApp2/Forms/AdminForm.cs). Класс `public sealed class AdminForm : Form` редактирует рабочую копию меню. Само окно не проверяет пароль: его открывает защищённый обработчик `CoffeeMachineControl.OpenAdmin()`, а переданный обработчик сохранения дополнительно проверяет доступ в главном окне.

Ключевые поля:

| Поле | Назначение |
|---|---|
| `_original : MachineConfiguration` | Исходная конфигурация: нужна, чтобы сохранить ID и прочие неизменяемые значения при создании новой версии через `with`. |
| `_draft : List<Beverage>` | Отдельный список напитков, который редактируется в окне. |
| `_save : Action<MachineConfiguration>` | Переданная функция окончательного сохранения и применения настроек. |
| `_list`, `_current` | Список напитков слева и индекс редактируемого напитка. |
| `_loading` | Отличает программное заполнение полей от действий пользователя; предотвращает лишние обработчики и взаимные переключения. |
| `_dirty` | Показывает наличие несохранённых правок для предупреждения при закрытии. |
| `_machineName`, `_name`, `_recipe`, `_color`, `_image` | Поля названия автомата, названия напитка, описания, цвета жидкости и имени изображения. |
| `_price`, `_volume`, `_seconds` | Числовые поля цены, объёма и времени приготовления с установленными границами. |
| `_enabled`, `_milk`, `_coffee` | Признаки доступности, наличия молока и кофейного типа напитка. |
| `_preview`, `_previewTitle`, `_status` | Картинка и подпись предварительного просмотра, строка состояния. |

| Метод | Что делает |
|---|---|
| `public AdminForm(MachineConfiguration configuration, Action<MachineConfiguration> save)` | Сохраняет исходную конфигурацию и обработчик; создаёт `_draft` через `configuration.Menu.ToList()`. Строит редактор, назначает ограничения полей, события изменения и подтверждение закрытия. Загружает первый напиток через `ReloadList(0)`. |
| `private static NumericUpDown Number(int min, int max, int decimals = 0)` | Создаёт числовое поле с минимальным и максимальным значениями, числом знаков после запятой и разделителем тысяч. |
| `private static void Row(TableLayoutPanel panel, int row, string title, Control field)` | Добавляет в строку таблицы подпись и соответствующее поле, задавая заполнение ячейки и отступы. |
| `private void DrawDrink(object sender, DrawItemEventArgs e)` | Рисует элемент списка напитков: фон выделения, изображение, название, цену, объём и отметку выключенного напитка. Это обработчик `ListBox.DrawItem` для режима `OwnerDrawFixed`. |
| `private void ReloadList(int selected)` | Включает `_loading`, обновляет все элементы списка из `_draft`, выбирает нужный индекс, затем загружает поля выбранного напитка. `BeginUpdate()` / `EndUpdate()` сокращают лишнюю перерисовку списка. |
| `private void LoadEditor(int index)` | Под защитой `_loading` переносит значения выбранного напитка в поля, запоминает `_current`, затем обновляет предварительный просмотр. |
| `private Beverage ReadEditor()` | Возвращает новую запись напитка через `_draft[_current] with { ... }`, заполняя её значениями полей и убирая пробелы по краям текстов. Существующий объект напитка не изменяет. |
| `private bool ApplyEditor()` | Получает новую запись через `ReadEditor()`, вызывает `Validate()` и только при успехе заменяет напиток в `_draft` и списке. При `ArgumentException` показывает ошибку и возвращает `false`. |
| `private void SelectionChanged(object sender, EventArgs e)` | Перед переходом к другому напитку применяет текущие поля к черновику. Если они невалидны, возвращает выделение на старый элемент; иначе загружает новый напиток. |
| `private void Edited(object sender, EventArgs e)` | Игнорирует программное заполнение; для правки пользователя устанавливает `_dirty`, меняет строку состояния и обновляет предварительный просмотр. |
| `private void UpdatePreview()` | Показывает текущее имя, цену, объём и изображение ещё до сохранения. Проверяет отсутствие `/` и `\` в имени файла перед загрузкой изображения для просмотра. Полная проверка напитка выполняется при применении и сохранении. |
| `private void Add(object sender, EventArgs e)` | Ограничивает меню 100 напитками, сначала применяет поля текущего напитка, затем добавляет новый `Beverage`, отмечает изменения и открывает его для редактирования. |
| `private void Remove(object sender, EventArgs e)` | Не разрешает удалить последний напиток. После подтверждения удаляет текущий элемент из черновика и выбирает соседний. На работающий автомат это повлияет только после сохранения. |
| `private void ImportImage(object sender, EventArgs e)` | Открывает выбор PNG/JPEG/BMP, проверяет размер файла до 10 МБ и размеры изображения до 4096 × 4096. Сохраняет его как PNG под новым GUID-именем в папке пользовательских картинок и подставляет имя в поле. Ошибки показывает через `Error()`. |
| `private void Error(string text)` | Красит строку состояния в красный цвет и показывает окно с пояснением ошибки. |
| `private void Save(object sender, EventArgs e)` | Сначала применяет текущие поля. Создаёт новую конфигурацию через `_original with { Name = ..., Menu = _draft.ToArray() }`, проверяет её, вызывает `_save(config)`. Только при успехе снимает `_dirty`, устанавливает `DialogResult.OK` и закрывает окно. Ошибки проверки/доступа/записи оставляют редактор открытым. |

`ToList()` копирует список, но изначально элементы-напитки остаются теми же объектами. Это безопасно в принятой модели редактирования: `Beverage` — неизменяемая запись с `init`-свойствами, а `ReadEditor()` создаёт новую запись через `with`, после чего она заменяет элемент только в черновике. `with` сам по себе не означает глубокое копирование любого вложенного объекта; здесь коллекция явно заменяется новым массивом при сохранении.

События `TextChanged`, `ValueChanged` и `CheckedChanged` ведут к `Edited()`. Событие `SelectedIndexChanged` ведёт к `SelectionChanged()`. Кнопка отмены вызывает `Close()`. В `FormClosing` при `_dirty` и результате, отличном от `OK`, появляется подтверждение закрытия без сохранения.

Числовые ограничения редактора: цена от 1 до 9999 рублей с двумя знаками после запятой, объём 30–1000 мл, приготовление 2–60 секунд. Название автомата ограничено 40 символами, напитка — 60, описание — 200, имя изображения — 100. Отключить все напитки можно, но удалить последний рецепт нельзя.

Импорт картинки выполняет запись сразу. Поэтому отмена всего редактора не удаляет уже импортированный файл: настройки не сохранятся, но неиспользуемая картинка останется в папке `Images`. Это реальное ограничение текущего кода, а не откат файловой операции.

## `PreparationMode` и `PreparationView` — рисунок приготовления

Файл: [PreparationView.cs](../CoffeeMachineApp2/Forms/PreparationView.cs). Перечисление `PreparationMode` имеет три значения: `Idle` — ожидание, `Brewing` — приготовление, `Ready` — готовая чашка. | `_progress` / `Progress` | Прогресс 0–1; присваиваемое значение ограничивается этим диапазоном. |
| `_liquid` / `LiquidColor` | Цвет напитка. |
| `_hasMilk` / `HasMilk` | Включает изменение цвета при добавлении молока и пену. |

| Метод | Что делает |
|---|---|
| `public PreparationView()` | Включает самостоятельную отрисовку и двойную буферизацию, задаёт исходный размер 260 × 200. |

## `ImageLoader` — загрузка и повторное использование картинок

Файл: [ImageLoader.cs](../CoffeeMachineApp2/Forms/ImageLoader.cs). `internal static class ImageLoader` выдаёт изображение напитка. Если загрузить файл нельзя, возвращает нарисованную заглушку с чашкой.

| Поле / свойство | Назначение |
|---|---|
| `Cache : Dictionary<string, Image>` | Хранит уже полученные изображения по имени файла, чтобы не читать их с диска при каждой перерисовке. |
| `Placeholder` | Одна общая картинка-заглушка, создаваемая при инициализации класса. |
| `CustomImageDirectory` | Путь к папке `Images` рядом с пользовательским `machines.json`; на Windows это `%LOCALAPPDATA%\CoffeeMachineApp\Images`. |

| Метод | Что делает |
|---|---|
| `public static Image Load(Beverage beverage)` | Ищет `beverage.ImageFile` в кеше. При отсутствии пробует загрузку с диска, заменяет неудачный результат заглушкой, запоминает его и возвращает. |
| `private static Image LoadFromDisk(string fileName)` | Сначала ищет файл в пользовательской папке `Images`, затем в `Assets` рядом с программой. Открывает поток, читает картинку и возвращает отдельную копию `Bitmap`, чтобы после закрытия потока файл не оставался заблокированным. При любой пойманной ошибке возвращает `null`. |
| `private static Image CreatePlaceholder()` | Создаёт `Bitmap` размером 300 × 225 и рисует блюдце, чашку, ручку, кофе и пар. Освобождает временные графические объекты, возвращая готовое изображение. |

Явно объявленного конструктора нет. Кеш и заглушка живут в течение работы процесса; отдельного метода очистки кеша в текущем коде нет. Картинки, возвращённые `Load()`, общие: например, `AdminForm` использует их для просмотра и списка. Карточки меню создают свои уменьшенные копии через `new Bitmap(...)`; эти копии освобождаются при перестроении меню и при удалении автомата.

Кеш хранит и результаты неудачной загрузки. Если файл с тем же именем заменить или добавить вручную во время работы, уже закешированное изображение автоматически не обновится. Для импортируемых через редактор картинок создаются новые GUID-имена, поэтому обычная смена картинки получает новый ключ кеша. Ошибка чтения картинки не останавливает приложение, но её точная причина пользователю из `ImageLoader` не показывается.

## Что сказать о событиях, времени и ресурсах на защите

- `Click`, `Tick`, `Paint`, `Resize`, `FormClosing` — события Windows Forms. Запись `+=` подключает обработчик. В коротких случаях он записан лямбдой `(s, e) => ...`, в более длинных — отдельным методом.
- `Action<MachineConfiguration>` — переданная функция, принимающая конфигурацию. Это позволяет редактору вызвать сохранение, не зная, как главное окно собирает настройки соседних автоматов и где хранится JSON.
- `ShowDialog(this)` открывает модальное окно: пока оно открыто, родительское окно не принимает обычные действия пользователя. Это используется для редактирования и входа администратора.
- Все перечисленные таймеры — `System.Windows.Forms.Timer`. Их обработчики выполняются в потоке интерфейса. `async`, `await`, фонового приготовления и отдельных потоков для каждого автомата здесь нет. Несколько автоматов выглядят работающими одновременно, потому что короткие обработчики их таймеров по очереди обновляют независимые состояния.
- `Stopwatch` нужен для прошедшего времени. Интервал таймера 40 мс — желаемая частота обновления, а не обещание точного вызова каждые 40 мс. При задержке интерфейса следующий кадр всё равно вычислит прогресс из прошедших секунд.
- `Invalidate()` просит перерисовать элемент, а `OnPaint()` описывает, что рисовать. Установка флага или свойства сама по себе не рисует новый кадр немедленно.
- `SuspendLayout()` / `ResumeLayout()` временно откладывают перерасчёт расположения при массовой замене карточек. `try/finally` в `BuildMenu()` гарантирует возобновление разметки даже при исключении.
- `Dispose()` освобождает ресурсы, которым недостаточно просто ждать сборщика мусора: таймеры, графические изображения и подсказки. `using` выполняет такое освобождение для временных объектов и модальных окон.
- Масштабирование учитывается через `AutoScaleMode.Dpi`, процентные ячейки таблиц, `LogicalToDeviceUnits()` и масштабирование координат рисования. В карте и лотке шрифты заданы в пикселях логической сцены, чтобы общий графический масштаб не увеличивал их повторно как шрифты в пунктах.

Реальные границы реализации: это настольный симулятор для Windows, без связи с банковским терминалом и физической выдачей напитков. Изображение приготовления показывает время и выбранные параметры, но не управляет нагревателем или запасами ингредиентов. В одном окне допускается до 12 автоматов, у каждого — до 100 рецептов, а в меню покупателя одновременно видно шесть карточек. Рабочие заказы и анимации не восстанавливаются после закрытия программы; сохраняются настройки, меню и данные доступа. Прокрутка меню устранена, но прокрутка общего пространства автоматов и списка рецептов в админке остаётся допустимой частью интерфейса.
