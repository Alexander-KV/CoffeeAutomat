# BEAN & CUP — симулятор кофейных автоматов

Приложение написано на **C# / .NET 8 / Windows Forms**. Браузер, сервер и база данных для работы не нужны.

Тёмный корпус с латунным акцентом, светлый экран с карточками напитков, фильтры по наличию молока, отдельный терминал оплаты и подсвеченная ниша выдачи. Сахар, молоко и сироп меняются крупными кнопками; стоимость пересчитывается сразу. Терминал показывает внесённую сумму и остаток к оплате, карта вставляется в слот и возвращается с анимацией, а сдача появляется в отдельном лотке. Ниша выдачи показывает этап приготовления и прогресс.

## Открыть и запустить

Нужна Windows и Visual Studio 2022 с нагрузкой «Разработка классических приложений .NET» и .NET 8 SDK.

`global.json` предпочитает SDK 8, но допускает более новый SDK, если 8 отсутствует. Целевая версия приложения остаётся .NET 8. Установленный SDK должен поддерживаться вашей версией Visual Studio.

Если Visual Studio пишет «Не удалось найти пакет SDK для .NET версии 8.0.100» или не может разрешить SDK из `global.json`:

1. Установите **.NET 8 SDK для Windows x64** с https://dotnet.microsoft.com/download/dotnet/8.0 — именно SDK, а не только Runtime. Точная версия 8.0.100 не требуется: подходит актуальный SDK 8.0.xxx.
2. Перезапустите Visual Studio. Для .NET 8 нужна Visual Studio 2022 версии 17.8 или новее и нагрузка «Разработка классических приложений .NET».
3. В терминале команда `dotnet --list-sdks` должна показывать установленный SDK 8. Если SDK отсутствует в списке, проверьте установку и перезапустите терминал.

Для обычного запуска собранного `net8.0-windows` нужен .NET Desktop Runtime 8; установщик SDK 8 для Windows включает его. В готовой self-contained сборке runtime уже включён.

1. Откройте `CoffeeAutomat.sln` в корне репозитория.
2. Назначьте `CoffeeMachineApp` запускаемым проектом и нажмите F5.
3. Выберите напиток, настройте сахар, молоко и сироп, перейдите к оплате.
4. Внесите наличные или выберите оплату картой и нажмите на карту над терминалом, чтобы вставить её. Подтвердите оплату.
5. После приготовления нажмите **«Забрать кофе»**. Сдачу заберите отдельным нажатием на лоток; карту — нажатием на слот терминала. Получение чашки не забирает сдачу или карту автоматически.

Или из корня репозитория:

```sh
dotnet run --project CoffeeMachineApp2/CoffeeMachineApp.csproj
```

Карта — демонстрационная, без ограничения средств; реальные платежи не выполняются. Заказы, внесённые наличные, незабранные напитки, сдача и положение карты существуют до закрытия программы; меню, состав автоматов и пароль администратора сохраняются.

## Несколько автоматов рядом

Создание, копирование и удаление автоматов доступны только после входа через общую кнопку **«Администратор»** в заголовке окна.

- **«+ Копировать автомат»** под нужным автоматом создаёт соседа с копией его текущего меню и новым ID.
- **«+ Новый автомат»** в заголовке создаёт автомат со стандартным меню.
- Каждый экземпляр имеет собственные настройки, выбор напитка, внесённые деньги, состояние демо-карты и таймер приготовления. Изменение цены в копии не меняет оригинал.
- Можно одновременно готовить напитки в нескольких автоматах. В узком окне используйте горизонтальную и вертикальную прокрутку. Максимум — 12 автоматов.
- Список автоматов восстанавливается после перезапуска. Копирование переносит настройки и создаёт свободный автомат без активного заказа.
- **«Убрать автомат»** удаляет свободный автомат с подтверждением. Меню соседей сохраняются; последний автомат удалить нельзя.

Для создания автомата в коде передайте модель, обработчик сохранения и общий `AdminAccess` компоненту `CoffeeMachineControl`; пример подключения находится в `Forms/MainForm.cs`. Отдельный класс формы для второго автомата не нужен.

## Админ-панель и JSON

Программа всегда запускается в режиме покупателя. Нажмите общую кнопку **«Администратор»** в заголовке окна: при первом входе задайте свой пароль длиной минимум 6 символов и повторите его для подтверждения. При последующих входах нужен этот пароль. Кнопка **«Выйти из админ-режима»** возвращает все автоматы в режим покупателя.

Войти в админ-режим можно, только когда все заказы завершены или отменены, а кофе, карты и сдача получены. Если напиток только выбран, нажмите «Сбросить». Во время оплаты кнопка «← Назад» возвращает к выбору, сохраняет рецепт и возвращает внесённые наличные; затем выбор можно сбросить. Если карта вставлена, сначала заберите её. Уже оплаченный заказ нужно завершить.

В админ-режиме покупки на всех автоматах приостановлены. Только здесь доступны **«Настройки»**, добавление, копирование и удаление автоматов, редактирование меню, цен и прочих параметров. В режиме покупателя эти элементы управления скрыты, а сохранение настроек защищено проверкой доступа.

В панели слева находится список напитков, справа — редактор выбранного рецепта с предпросмотром. Можно изменить название автомата, добавить и удалить напиток, задать название напитка, цену, объём, рецепт, картинку, цвет, время приготовления, наличие молока и доступность. Флаг «Кофейный напиток» выбирает этапы анимации для кофе или горячего шоколада. Переключение «В продаже» отключает возможность покупки, сохраняя рецепт. Числовые поля ограничены допустимыми значениями.

Нажмите **«Сохранить изменения»**, чтобы записать JSON и применить изменения. «Отмена» закрывает редактор без изменений, с подтверждением при наличии правок. Ошибки ввода или записи показываются явно; неудачная запись не меняет меню в работающем автомате.

Файл настроек на Windows:

```text
%LOCALAPPDATA%\CoffeeMachineApp\machines.json
```

Он создаётся при первом запуске и содержит список автоматов и меню каждого. Отдельного файла на каждый рецепт не требуется. Кириллица сохраняется читаемо. Файл не лежит рядом с `.exe`, поэтому запуск из защищённой папки и новая сборка не уничтожают настройки. Для переноса на другой компьютер скопируйте папку `%LOCALAPPDATA%\CoffeeMachineApp` целиком вместе с загруженными изображениями. Редактировать JSON вручную следует при закрытой программе.

Рядом находится `admin-access.json`: он создаётся при первом успешном задании пароля и хранит случайную соль и PBKDF2-SHA256-хеш, а не пароль открытым текстом. После перезапуска снова требуется вход. Повреждённый файл доступа вызывает ошибку и не заменяется автоматически новым паролем.

Сохранение `machines.json` атомарное: запись временного файла, сброс на диск, затем замена. Если этот JSON повреждён, программа показывает путь и ошибку и **не перезаписывает** файл стандартным меню. Исправьте его или переместите в резервную копию, чтобы создать стандартный файл при следующем запуске. Одновременно открывать несколько экземпляров программы с одним файлом настроек нельзя.

Кнопка **«Загрузить…»** импортирует PNG, JPEG или BMP прямо из админки, без пересборки. Импортированные картинки сохраняются в `%LOCALAPPDATA%\CoffeeMachineApp\Images`, поэтому не теряются при обновлении программы. Допускаются изображения до 10 МБ и до 4096 × 4096 пикселей. При отмене редактора неиспользованная импортированная картинка остаётся на диске; меню при этом не меняется.

Также можно выбрать готовое имя из `Assets`, например `coffee3.png`. Пустое поле или отсутствующий файл отображается как чашка-заглушка. Цвет задаётся как `#RRGGBB`.

## Простая ООП-структура

В предметной модели осталось **6 классов вместо 12**, без искусственной иерархии `Product → Beverage → Coffee`:

| Тип | Ответственность |
| --- | --- |
| `Beverage` | Неизменяемые данные рецепта и проверка значений; новый вид кофе — запись в меню |
| `CoffeeOrder` | Неизменяемый заказ одной чашки и расчёт итоговой цены |
| `MachineConfiguration` | Сохраняемые настройки и создание независимой копии |
| `CoffeeMachine` | Инкапсулирует состояния, заказ и переходы между выбором, оплатой, приготовлением и выдачей |
| `CashPayment`, `CardPayment` | Разные реализации `IPaymentMethod`; автомат вызывает единый метод оплаты |

Дополнительно `JsonMachineStore` реализует `IMachineStore` и отвечает за сохранение настроек; `AdminAccess` хранит хеш пароля и проверяет доступ. `MainForm` расставляет автоматы и переключает общий режим; `CoffeeMachineControl` отображает один автомат; `AdminLoginForm` принимает пароль; `AdminForm` редактирует копию настроек. UI не вычисляет цены и не списывает деньги. Неизменяемые записи (`record`) позволяют безопасно создавать изменённую копию через `with`.

Сахар 0–2 ложки бесплатный, 3–4 — фиксированная надбавка 10 ₽. Дополнительное молоко и сироп стоят по 30 ₽. При переходе с наличных на карту внесённые деньги возвращаются. После оплаты менять или отменять заказ нельзя.

## Проверки

Из корня репозитория:

```sh
dotnet build CoffeeAutomat.sln
dotnet run --project CoffeeMachineApp.Tests/CoffeeMachineApp.Tests.csproj
```

`CoffeeMachineApp.Tests` — консольный набор проверок на C# без сторонних пакетов. Выводит PASS/FAIL и возвращает ненулевой код при ошибке. Он проверяет оплату, переходы состояний, возвраты, отдельное получение кофе, карты и сдачи, неограниченную демо-карту, дробные цены, независимость автоматов, новые напитки, сохранение и повторную загрузку JSON, отклонение некорректных настроек и ошибки записи. Проверки доступа охватывают создание пароля, правильный и неверный пароль, выход, повторный запуск, защиту операций и повреждение файла доступа.

На Linux можно собирать Windows-проект и выполнять проверки модели/JSON, но запуск интерфейса и визуальная проверка Windows Forms требуют Windows. Готовые `bin`, `obj` и локальные настройки Visual Studio исключены из Git и создаются при сборке.

## Сборка для Windows без установки .NET

```sh
dotnet publish CoffeeMachineApp2/CoffeeMachineApp.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -o artifacts/windows
```

Скопируйте содержимое папки публикации целиком: `CoffeeMachineApp.exe` и `Assets`. В такой сборке .NET уже включён; Visual Studio и отдельный runtime на компьютере покупателя не требуются.
